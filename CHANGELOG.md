# История изменений — OneCatalog Import (1С-Битрикс)

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
нумерация версий — по [семантическому версионированию](https://semver.org/lang/ru/).

Версия задаётся в `onecatalog.import/install/version.php`. Соответствие стандарту
интеграции: **v1.0** (см. [onecatalog-standard](https://github.com/OneCatalog/onecatalog-standard)).

## [Не выпущено] — бэклог

### Реализовано на `dev` — §13 Синхронизация цен и остатков (версия модуля 0.2.0)
- **`B2bApi`** — клиент B2B-фида (`retailer-share-products`, `url_key` в пути +
  `private_key` в query; новый формат: верхнеуровневые `suppliers`/`warehouses`/
  `regions`, в оффере `supplier_id`), пагинация, разведка справочников.
- **`PriceStockSync`** по принципу **scan-and-diff** (§13.4): скан сравнивает
  сигнатуры цены/остатка в памяти (префетч `public_id`→элемент+сигнатура одним
  запросом), пишутся только изменившиеся. Цена — нативный **`CPrice`** (тип цены +
  валюта), стратегия (мин./приоритет/конкретный) × приоритет регионов; остаток —
  сумма по складам → **`CCatalogProduct.QUANTITY`** (дробные поддержаны). Коды
  поставщиков → свойство `OC_SUPPLIER_CODE`; сигнатура → `OC_PRICESTOCK_SIG`.
  Событие `OnAfterPriceStockUpdated` (сырые офферы) — для раскладки по регионам/складам.
- **Страница «Цены и остатки»** (admin): ключи B2B, стратегия, тип цены, валюта,
  приоритеты (id), ручной запуск **браузерным степпером** (без cron) + прогресс/лог.
  Пункт меню, RU/EN-локализация, дефолты опций при установке.
- Чистые резолверы (цена/остаток/сигнатура) покрыты тестом на реальном fixture.
- ⚠️ Следующий инкремент: промо отдельным типом цены / `CCatalogDiscount`; остатки по
  складам через `CCatalogStoreProduct` (нативно); журнал обновлений и уведомления;
  drag-and-drop приоритетов; учёт конфликта с обменом 1С (отдельный тип цены/склад).

### Реализовано на `dev` (ядро импорта одного товара, §0 шаг 1)
- **`Taxonomies`**: find-or-create свойств инфоблока (`L`/`N`/`S`) по стабильному
  коду; enum по стабильному XML_ID и по VALUE (label, регистронезависимо, §5.1);
  разделы-категории с деревом и фолбэком по имени.
- **`ProductImporter`**: импорт одного товара по `public_id` —
  идемпотентность по свойству `OC_PUBLIC_ID` (не `XML_ID`); `OC_ARTICLE`=`article`
  отдельно (§5.2); название/`CODE`/`ACTIVE` (статус и CODE только при создании, §5.6);
  категории-дерево по `parent_category`; характеристики text→список,
  boolean→Да/Нет (false по умолчанию, §5.6), numeric→свойство-число; габариты через
  `Units` → `CCatalogProduct` (вес г / размеры мм); **цена не задаётся** (§5.6);
  события `OnBeforeImportProduct` (фильтр payload) и `OnAfterProductImported`
  (полный payload — сайтовый слой §8).
- Построение цепочки категорий вынесено в чистую `buildCategoryChain()` — покрыто
  тестом на реальном fixture (`categories.json`), включая защиту от циклов.

### Реализовано на `dev` (UI: picker + импорт по списку, §2.4, §6)
- **Виджет-пикер OneCatalog** (`picker-loader.js`): iframe на `tools.onecatalog.net`,
  выбор через `postMessage` по `productPublicIds`; **origin зафиксирован настройкой**
  `PICKER_BASE` (дефолт `https://tools.onecatalog.net`) и проверяется на каждое
  сообщение (`event.origin`). Fallback — импорт по вставленному списку `public_id`.
- **AJAX-степпер** (`admin-import.js` + ветка `ajax=Y` admin-страницы): режет
  выбор на порции по «шагу импорта», шлёт последовательно с `check_bitrix_sessid`
  и проверкой прав (≥W), показывает прогресс и лог.
- **`Queue::importBatch()`**: синхронный импорт порции через `ProductImporter`,
  деградация без падений (битый id не валит порцию), лог последних 100 результатов.
- **Админка**: страница «Импорт товаров» (picker + список + прогресс), страница
  «Настройки» (токен, базовый URL, origin picker'а, язык, инфоблок, шаг, статус
  новых, флаги импорта), пункт меню; обёртки `/bitrix/admin` и JS `/bitrix/js`
  копируются при установке. Настройка `PICKER_BASE`.

### Реализовано на `dev` (изображения, §2.3, §5.3)
- **`Media`**: обложка + галерея. Ручное скачивание (`Api::fetchBinary`) + MIME по
  содержимому (`finfo`) + корректное расширение в имени (URL без расширения, §2.3);
  выбор размера (`max` с токеном, иначе `min`).
- **Дедуп по контент-ключу** `sha1(path)`: path извлекается из base64-префикса URL
  `media_files` (до точки-подписи — подпись/токен волатильны); один файл скачивается
  один раз и переиспользуется. Таблица `onecatalog_media` (`CONTENT_KEY`/`SIZE`/
  `FILE_ID`/`SHARED`), т.к. у `CFile` нет места под мету.
- **Трекинг качества**: при появлении лучшего размера (например, добавили токен)
  файл перекачивается и заменяется; **общие (`SHARED`) файлы не удаляются** (§5.3).
- Обложка → `PREVIEW_PICTURE`/`DETAIL_PICTURE`, галерея → множественное свойство-файл
  `OC_MORE_PHOTO`. Идемпотентность по подписи набора (`OC_MEDIA_SIG` = имена+размер):
  без изменений и без улучшения качества медиа пропускается (не плодим копии).
- Контент-ключ/выбор размера покрыты тестами на реальных URL из fixture.

### Реализовано на `dev` (справочные сущности, §3, §7)
- **`BrandImporter`** / **`CountryImporter`** / **`CollectionImporter`** + теги:
  дефолт-адаптер «свойство-список (L)» (`OC_BRAND`/`OC_COUNTRY`/`OC_COLLECTION`/
  `OC_TAGS`), find-or-create по label, стабильный XML_ID enum по id OneCatalog (§5.1).
  Импорт страны выключен по умолчанию (§7); бренд/коллекции — включены.
- Доп. поля справочников (страна/год/сайт бренда, `link_3d`/`link_official_site`
  коллекции) и **лого** уходят в события `OnAfterBrandImported` /
  `OnAfterCountryImported` / `OnAfterCollectionImported` (полная сущность + результат,
  §8). Лого бренда/коллекции кэшируется через `Media` (дедуп общих файлов, §5.3).
- Хелпер `Taxonomies::ensureListValue()` (свойство-список + enum) для этих сущностей.
- ⚠️ Адаптеры **HL-справочник / раздел / отдельный инфоблок** — следующий инкремент
  (требуют `highloadblock` / создание инфоблока). Дефолты `*_TARGET_TYPE` = `list`.

### Реализовано на `dev` (ручной маппинг характеристик, §5.4, §7)
- **Строгий ручной маппинг**: страница «OneCatalog → Маппинг характеристик» —
  таблица характеристик из `/specifications/` (один запрос `limit=1000`), на каждую
  выбор свойства целевого инфоблока; для `boolean` — значения терма для true/false.
  Привязка хранится по стабильному `specification_id` (опция `SPEC_MAP`), не по
  переводимому названию.
- При ВКЛ (`SPEC_MANUAL_MAPPING`) импортируются **только сопоставленные**
  характеристики (строгий режим), прочие пропускаются; при ВЫКЛ — прежнее поведение
  «по имени / создать». `ProductImporter::resolveOptions()` объединён в единый путь.
- Пункт меню + языковые файлы (RU/EN).

### Запланировано (следующие инкременты)
- Адаптеры «тип объекта + цель»: HL-справочник, раздел, отдельный инфоблок коллекций.
- `Queue` (агент `CAgent`): фоновый фолбэк через таблицу `onecatalog_queue`.
- Коллекция/бренд/страна: адаптеры «тип объекта + цель».
- Ручной маппинг характеристик (строгий режим) по `specification_id`.

## [0.1.0] — 2026-06-16

### Добавлено
- **Фундамент модуля** `onecatalog.import`:
  - манифест/установка (`install/index.php`): проверка зависимостей `iblock`+`catalog`,
    создание таблиц `onecatalog_queue`/`onecatalog_media`, дефолты опций, регистрация
    агента очереди.
  - автозагрузка классов (`include.php`, namespace `OneCatalog\Import`).
  - `Api` — клиент Wiki API на D7 `HttpClient`: base/token/lang, обёртка `{data,success}`,
    справочники одним запросом (`limit=1000`) с дочиткой по `meta.counts`, ошибки → `null`.
  - `Units` — конвертер единиц (вес→граммы, размеры→миллиметры) с нормализацией
    локализованных подписей; покрыт тестом.
  - `Settings` — опции поверх `Option`: приоритет константы над токеном, кламп шага ≥10,
    язык только из списка.
  - языковые файлы `lang/ru` + `lang/en` для установки.
- Каркасы слоёв `Media`/`Taxonomies`/`*Importer`/`Queue` с сигнатурами и планом.
- Документация: план порта и ответы в `docs/`.
